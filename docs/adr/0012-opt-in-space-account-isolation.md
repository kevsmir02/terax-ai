# Opt-in per-Space agent account isolation

Status: Accepted (extends [ADR-0003](0003-spaces-organize-without-isolating.md))

Decided on 2026-11-14: allow each Space to opt into **Account isolation** (`default` off on creation, toggleable later), binding its terminal sessions and external-agent launches to a Space-owned **Account context** under the existing Linux user rather than OS sandboxing or shell-wide `$HOME` / `XDG_*` relocation. Initial `v1` isolated support covers Claude Code (`CLAUDE_CONFIG_DIR`), Pi (`PI_CODING_AGENT_DIR`), and OpenCode (a prepended `opencode` PATH shim setting per-Space `XDG_DATA_HOME`, `XDG_STATE_HOME`, `XDG_CACHE_HOME`, selective `OPENCODE_CONFIG_DIR`, and `--standalone` so `opencode.db` and `service.json` isolate without relocating XDG paths for `fish`, `git`, or `nvim`), while fixing Codr's launcher and detector command from desktop `"antigravity"` to `"agy"` for shared Spaces and deferring `agy` (alongside `codex`, `gemini`, `grok`) as blocked in isolated Spaces until upstream provides an official config-directory override. Keep project checkouts, repo-local configs (`.mcp.json`, `.claude/`), Git/SSH/cloud tools, and third-party MCP/memory stores shared outside isolation scope. Store private **Agent profile** state under `$XDG_DATA_HOME/codr/space-profiles/<space-id>/` (`0700`, keyed by stable `SpaceMeta.id`), live-sharing non-secret resource directories (`CLAUDE.md`, `skills/`, `agents/`, `plugins/` for Claude; `extensions/`, `skills/`, `prompts/`, `themes/`, `npm/` for Pi; shareable entries excluding `service.json`/`cli.json` in `OPENCODE_CONFIG_DIR` for OpenCode) and keeping enabled Codr notification hooks synced, while seeding initial `settings.json` on creation and keeping `.claude.json` fresh per Space so credentials, sessions, caches, and databases remain strictly private. Maintain authoritative Space isolation and pending-tombstone state in Rust so `pty_open` fails closed on setup, shim, or incompatible agent updates without falling back to host credentials; re-prepend Space shims and scrub ambient provider keys (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `OPENCODE_API_KEY`, `GEMINI_API_KEY`, unless set on `SpaceMeta.env`) after user rc files in Bash, Zsh, and Fish (`-C`) alongside launcher blocks and blocking shims for unsupported agents. Enforce **Account context** compatibility across UI and lifecycle: leave `$BROWSER` / `xdg-open` untouched with clear browser-account and local-vs-remote-revocation guidance; allow live drag of non-terminal tabs anywhere and terminal tabs across compatible contexts while offering guarded close-and-recreate across incompatible contexts; preserve non-terminal tabs and restart all terminal panes (busy and idle) on mode toggle; retain disabled private profiles visibly until explicitly cleared; stop Space process groups before atomic tombstone-rename deletion with crash-recovery sweeping; and keep secrets, tokens, auth file contents, and resolved keys out of `SpaceMeta`, frontend state, CLI args, logs, recovery storage, and `pty_diagnostics`. Rejected: OS sandboxing (`bubblewrap` / user namespaces), shell-wide `$HOME` or `XDG_*` relocation, per-binary fake `$HOME` + D-Bus-stripping wrappers for `agy`, fragile mutable JSON symlinking/auto-merging for `settings.json` or `~/.claude.json`, `$BROWSER` hijacking, and shared OpenCode background daemons across Spaces. Consequence: users maintain installations, skills, extensions, OpenCode configs, and Claude plugins once while isolating accounts cleanly against accidental wrong-account execution, same-user malicious-code containment remains explicitly out of scope, and future Space duplication features must clone organization/layout metadata only rather than credentials or profile directories.
