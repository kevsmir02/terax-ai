# Publish under this fork's own identity, endpoint and signing key

The fork must ship stable Linux packages without borrowing upstream's name, release channel or trust. Decided on 2026-11-13: the publication identity is the product name `Terax Workspace`, the release owner/repository `kevsmir02/terax-ai`, and the update endpoint that repository's latest release asset; the first stable line is `1.0.0` rather than upstream's `0.9.x` so the fork owns a version line that cannot drift into a tag upstream may also cut, and release notes still state the upstream revision it derives from. Authenticity rests on a minisign key generated offline by the maintainer, passphrase-protected, with the secret never entering the repository, CI or an issue body; only the public key, its fingerprint and non-secret configuration are committed, together with an offline recovery and replacement procedure that never bypasses verification. Managed DNF/APT repositories remain deferred, so native package/repository trust is a separate promise from artifact authenticity, and a failure in either fails closed rather than falling back. A tag produces a draft release that a human publishes; the gate refuses publication while identity or trust is missing but never publishes on its own. Rejected: staying on the provisional `.invalid` identity (no release becomes possible and the refusal becomes the product), reusing upstream's identity or keys (a silent migration of someone else's users onto this fork's artifacts), and GPG-signed repositories (more machinery than a deferred repository decision needs). Consequence: this is an unofficial fork publishing under a name that contains the upstream product's name, so every reader-facing surface must say it is unofficial and not affiliated with Crynta, and a rename later is a breaking change for the endpoint, package names and installed identity.
